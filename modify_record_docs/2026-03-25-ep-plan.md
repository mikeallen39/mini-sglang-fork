# 2026-03-25 EP Integration Plan

## Goal

Plan how to add Expert Parallelism (EP) for MoE models in `mini-sglang`, starting from the current GLM-4.7-Flash / GLM MoE support.

This is a design plan, not an implementation note.

## Current State In `mini-sglang`

### What already exists

- Tensor parallelism is already the main distributed abstraction.
- MoE execution exists through:
  - `python/minisgl/layers/moe.py`
  - `python/minisgl/moe/fused.py`
  - `python/minisgl/moe/torch_backend.py`
- Distributed communication currently exposes only:
  - `all_reduce`
  - `all_gather`

### What does not exist yet

- No EP-specific process group abstraction
- No expert ownership / local expert mapping
- No token dispatcher for EP
- No `all_to_all` primitive in `mini-sglang` distributed layer
- No EP-aware weight loading path
- No EP-aware MoE layer interface

## Key Observation

`mini-sglang` is currently structured around TP-first execution:

- attention and dense layers are TP-aware
- MoE is still effectively local to each TP rank, then reduced
- the MoE kernels assume the local rank already owns the experts it needs to execute

So adding EP is not a small flag flip. It requires a new execution shape:

1. route tokens to experts
2. dispatch tokens to the ranks that own those experts
3. run local experts only
4. combine expert outputs back to the original token order

## Useful Reference From `sglang`

The parts of `sglang` that matter most for EP are:

- EP group abstraction
  - `python/sglang/srt/distributed/parallel_state.py`
- token dispatch / combine
  - `python/sglang/srt/layers/moe/token_dispatcher/standard.py`
  - `python/sglang/srt/layers/moe/token_dispatcher/*`
- fused MoE layer with EP-aware local expert count / dispatcher hookup
  - `python/sglang/srt/layers/moe/fused_moe_triton/layer.py`

The important design idea is that `sglang` separates:

- global expert ids
- local expert ids on a rank
- dispatch / combine communication
- local expert kernel execution

That separation does not exist yet in `mini-sglang`.

## Recommended Scope For `mini-sglang`

Do not start with the full `sglang` EP stack.

The right path is staged:

### Stage 1: Minimal correctness-first EP

Target:

- support `ep_size > 1` for MoE
- keep attention and dense layers on the current TP path
- focus on correctness before communication optimality

Recommended first constraint set:

- only support `ep_size == tp_size`
- only support routed experts with contiguous ownership
- shared experts stay replicated
- no EPLB / redundant experts / elastic placement
- no DP-attention coupling yet

This gives the simplest mental model:

- each TP rank owns `num_experts / ep_size` routed experts
- router still produces global expert ids
- runtime maps global ids to local ids or remote ranks

### Stage 2: Real token dispatch EP

After correctness is proven:

- add true token dispatch/combine
- add `all_to_all`-style communication
- avoid executing useless experts on every rank

### Stage 3: Broader parallel plan

Only after Stage 2 is stable:

- consider `ep_size < tp_size`
- consider `moe_tp_size` separate from attention TP
- consider DP-attention + EP combinations
- consider load balancing / expert placement policies

## Concrete Changes Needed

### 1. Server / Engine Config

Add EP-facing config fields:

- `ep_size`
- optionally later: `moe_tp_size`

Initial validation rules:

- `ep_size in {1, tp_size}`
- only allow EP on MoE models
- initial version can reject unsupported combinations explicitly

Likely files:

- `python/minisgl/engine/config.py`
- `python/minisgl/server/args.py`
- `python/minisgl/engine/engine.py`

### 2. Distributed Groups

Add EP-aware group/state management.

Need at least:

- global TP group
- MoE EP group
- rank / world size helpers for EP

Initial requirement:

- if `ep_size == tp_size`, EP group can coincide with current TP world
- still expose EP helpers explicitly so the rest of the code does not hardcode TP assumptions

Likely files:

- `python/minisgl/distributed/info.py`
- `python/minisgl/distributed/impl.py`
- `python/minisgl/distributed/__init__.py`

### 3. Communication Primitives

Current `mini-sglang` distributed API is missing the main EP primitive.

Need to add:

- `all_to_all` or equivalent variable-size dispatch API

A staged approach is recommended:

- first correctness path:
  - `all_gather` hidden states across EP ranks
  - execute only local experts
  - sum / reduce outputs back
- later replace with:
  - true token dispatch
  - true token combine

Reason:

- correctness-first EP can be implemented with existing primitives faster
- true `all_to_all` is the right long-term solution, but adds more moving parts at once

### 4. MoE Layer Abstraction

Current `MoELayer` assumes:

- all local weights are directly executable
- only a final TP `all_reduce` is needed

That has to be split into:

1. router output
2. dispatch
3. local expert execution
4. combine

Likely files:

- `python/minisgl/layers/moe.py`
- `python/minisgl/moe/base.py`
- `python/minisgl/moe/fused.py`
- `python/minisgl/moe/torch_backend.py`

Recommended interface direction:

- introduce a dispatcher object or EP-aware MoE backend methods
- avoid burying dispatch logic inside the Triton kernel wrapper

## 5. Expert Ownership / Mapping

Need a clean mapping:

- global expert id -> owning EP rank
- global expert id -> local expert slot on that rank

Initial policy should be simple:

- contiguous partitioning of routed experts across EP ranks
- shared experts replicated locally on every rank

This mapping should be created once and reused by:

- weight loading
- runtime topk id remapping
- local kernel invocation

### 6. Weight Loading

EP requires expert weights to load differently from TP-only mode.

For routed experts:

- only load the local expert subset on each EP rank

For shared experts:

- either replicate
- or leave unsupported initially if the model needs a more complex handling path

This means the loader must stop assuming every rank owns all routed experts.

Likely file:

- `python/minisgl/models/weight.py`

### 7. Model-Specific Integration

GLM currently has a custom model path:

- `python/minisgl/models/glm4_moe_lite.py`

Need to decide whether EP support lives:

- generically in `MoELayer`
- or partially in GLM-specific code

Recommendation:

- keep expert dispatch generic
- keep model-specific code limited to router and MLA / attention differences

## Recommended Implementation Order

### Phase A

Add config and EP group plumbing.

Deliverables:

- `--ep-size`
- EP rank / size helpers
- explicit validation for supported combinations

### Phase B

Add local expert ownership and EP-aware weight loading.

Deliverables:

- local routed expert count
- global-to-local expert mapping
- local-only expert weight loading

### Phase C

Add a correctness-first EP execution path without true all-to-all.

Possible temporary strategy:

- gather hidden states and router decisions across EP ranks
- run only local experts using remapped local ids
- combine outputs back

This is not the final performance path, but it is much easier to validate.

### Phase D

Replace the temporary dispatch path with real token dispatch / combine.

Deliverables:

- new dispatcher abstraction
- `all_to_all`-style communication path
- local expert execution on packed dispatched tokens
- restore original token order during combine

### Phase E

Only after the above is stable:

- optimize overlap
- add better routing / load balancing
- extend to `ep_size < tp_size`
- consider DP-attention integration

## Risks

### Biggest technical risk

Trying to implement full-performance EP first.

That would couple too many changes at once:

- groups
- weight loading
- routing semantics
- dispatcher
- kernel expectations
- output combine

The likely outcome would be a long unstable debug cycle.

### Biggest design risk

Mixing TP and EP logic directly into existing fused MoE kernels before the ownership / dispatch model is clean.

The system needs an explicit boundary between:

- global routing ids
- local expert ids
- dispatch transport
- local execution

## Recommended First Milestone

The first milestone for EP in `mini-sglang` should be:

- GLM/Qwen/DeepSeek-style MoE model
- `ep_size == tp_size`
- local expert-only weight loading
- correctness-first dispatcher path
- one real functional test proving EP generates sane output

Only after that should the project attempt the faster true-dispatch path.
